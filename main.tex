\subsection{Persiapan Praktikum}
\par Pada praktikum pertemuan ini, saya berfokus pada penerapan \textit{mocking object} menggunakan Mockito untuk studi kasus modul \textbf{Library}. Proyek yang digunakan merupakan proyek Maven berbasis Java dan JUnit 5. Langkah awal yang saya lakukan adalah memastikan dependensi pengujian (JUnit 5) tetap tersedia pada \textbf{pom.xml}, kemudian menjalankan seluruh pengujian melalui fitur \textit{Run Test} di VS Code maupun melalui perintah \textbf{mvn test} untuk memastikan konfigurasi proyek berjalan dengan baik.

\par Untuk mengaktifkan Mockito pada proyek Maven ini, saya menambahkan dua dependensi pada \textbf{pom.xml} dengan scope \textbf{test}, yaitu \textbf{mockito-core} sebagai library utama Mockito dan \textbf{mockito-junit-jupiter} untuk integrasi Mockito dengan JUnit 5 (agar anotasi seperti \textbf{@Mock}, \textbf{@InjectMocks}, serta \textbf{@ExtendWith(MockitoExtension.class)} dapat digunakan dengan lancar pada kelas pengujian).

\subsection{Soal Praktikum}
\par Soal yang diminta pada pertemuan ini adalah sebagai berikut:
\begin{enumerate}
  \item Tambahkan fungsi untuk cek ketersediaan buku pada controller dan model. Cek ketersediaan buku berdasarkan id. Buatlah test method untuk method cek ketersediaan pada controller.
  \item Tambahkan class model \textbf{NotificationService} yang akan mengirimkan notifikasi apabila buku berhasil dipinjam atau dikembalikan. Urutan proses yang diharapkan (eksplor penggunaan fungsi \textbf{InOrder} untuk memastikan urutan pemanggilannya sesuai):
  \begin{enumerate}[label=\arabic*.]
  \item getAllBooks()
  \item Peminjaman(title, username)
  \item sendNotification(username, title)
  \end{enumerate}
  \item Meminjam buku (id buku). Buat 2 test scenario:
  \begin{itemize}
  \item Apabila tidak sedang dipinjam maka fungsi peminjaman buku akan dipanggil.
  \item Apabila buku sedang dipinjam, lakukan verifikasi bahwa fungsi peminjaman buku tidak dipanggil.
  \end{itemize}
\end{enumerate}

  \item \textbf{LibraryModel}: akan ditambahkan method \textbf{getBookById}, \textbf{isBookAvailable}, \textbf{borrowBook}, dan \textbf{returnBook} (sebagai titik interaksi yang diverifikasi pada unit test).

\end{enumerate}

\subsubsection{Identifikasi Stub dan Mock pada Kasus Ini}
\par Pada Mockito, \textit{stub} digunakan untuk mengatur perilaku objek dependency sehingga test dapat berjalan deterministik. Stub pada kasus ini adalah:
\begin{enumerate}
  \item \textbf{Stub ketersediaan buku}: \textbf{when(bookModel.isBookAvailable(1)).}\\
  \textbf{thenReturn(true)}.
  \item \textbf{Stub daftar buku}: \textbf{when(bookModel.getAllBooks()).thenReturn(books)}.
\end{enumerate}

\par Sementara itu, \textit{mock} digunakan untuk memverifikasi interaksi terhadap dependency. Mock pada kasus ini adalah:
\begin{enumerate}
  \item \textbf{verify(times)} untuk memastikan method dipanggil: \textbf{verify(bookModel, times(1)).} \textbf{borrowBook(...)}.
  \item \textbf{verify(never)} untuk memastikan method tidak dipanggil: \textbf{verify(bookModel,}\\
  \textbf{never()).} \textbf{borrowBook(...)}.
  \item \textbf{InOrder} untuk memverifikasi urutan pemanggilan dependency: \textbf{getAllBooks} $\rightarrow$ \textbf{borrowBook} $\rightarrow$ \textbf{sendNotification}.
\end{enumerate}

\begin{lstlisting}[language=Java, caption={LibraryControl setelah perubahan (cek availability, borrow by id, dan notifikasi)}, label={lst:librarycontrol-after}]
package com.example;

import java.util.List;

public class LibraryControl {

  private final LibraryModel model;
  private final NotificationService notificationService;

  public LibraryControl(LibraryModel model) {
    this(model, null);
  }

  public LibraryControl(LibraryModel model, NotificationService notificationService) {
    this.model = model;
    this.notificationService = notificationService;
  }

  public String SearchBooksAuthor(String tittle) {
    List<Book> books = model.getAllBooks();
    String result = "";
    for (Book book : books) {
      if (book.getTitle().equals(tittle)) {
        model.saveSearchKeyword(tittle);
        result = book.getAuthor();
      }

      // else result = "Book not found";
    }
    return result;
  }

  public boolean checkBookAvailability(int bookId) {
    return model.isBookAvailable(bookId);
  }

  public boolean borrowBookById(int bookId, String username) {
    List<Book> books = model.getAllBooks();
    Book bookToBorrow = null;
    for (Book book : books) {
      if (book.getId() == bookId) {
        bookToBorrow = book;
        break;
      }
    }

    if (bookToBorrow == null || bookToBorrow.isBorrowed()) {
      return false;
    }

    String title = bookToBorrow.getTitle();
    model.borrowBook(title, username);

    if (notificationService != null) {
      notificationService.sendNotification(username, title);
    }

    return true;
  }

  public boolean returnBookById(int bookId, String username) {
    List<Book> books = model.getAllBooks();
    Book bookToReturn = null;
    for (Book book : books) {
      if (book.getId() == bookId) {
        bookToReturn = book;
        break;
      }
    }

    if (bookToReturn == null || !bookToReturn.isBorrowed()) {
      return false;
    }

    String title = bookToReturn.getTitle();
    model.returnBook(title, username);

    if (notificationService != null) {
      notificationService.sendNotification(username, title);
    }

    return true;
  }
}

import java.util.List;

import org.junit.jupiter.api.Assertions;
import org.junit.jupiter.api.Test;

import org.mockito.InOrder;
import org.mockito.InjectMocks;
import org.mockito.Mock;
import org.mockito.Mockito;
import org.mockito.junit.jupiter.MockitoExtension;

@ExtendWith(MockitoExtension.class)

  private LibraryModel bookModel;

  @Mock
  private NotificationService notificationService;

  public void testSearchBooksAuthor() {

    books.add(new Book(1, "Intro OOP", "divi"));

    Mockito.when(bookModel.getAllBooks()).thenReturn(books);

    // stub

  public void testCheckBookAvailability_controller() {

    Mockito.when(bookModel.getAllBooks()).thenReturn(books);

\section{Kesimpulan}
\par Berdasarkan hasil praktikum pertemuan ini, saya memahami bahwa Mockito dapat digunakan untuk memisahkan pengujian unit dari ketergantungan eksternal dengan cara membuat \textit{mock} dan \textit{stub}. Dengan pendekatan ini, perilaku dependency seperti \textbf{LibraryModel} dan \textbf{NotificationService} dapat dikendalikan melalui stub (\textbf{when}--\textbf{thenReturn}), lalu interaksinya dapat diverifikasi melalui \textbf{verify}, \textbf{times}, dan \textbf{never}.

\par Selain itu, saya juga memahami bahwa pengujian tidak hanya memeriksa nilai keluaran, tetapi juga bisa memeriksa interaksi dan urutan proses. Pada studi kasus ini, fitur \textbf{InOrder} digunakan untuk memastikan urutan pemanggilan \textbf{getAllBooks()} $\rightarrow$ \textbf{borrowBook(title, username)} $\rightarrow$ \textbf{sendNotification(username, title)} sesuai dengan kebutuhan soal. Hasil pengujian menunjukkan seluruh skenario berhasil dijalankan sehingga implementasi fitur baru pada modul \textbf{Library} dapat dianggap berhasil.
